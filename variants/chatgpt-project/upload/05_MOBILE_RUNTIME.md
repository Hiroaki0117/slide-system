# ChatGPT Mobile Output and Recovery

## 1. 出力ファイル

チャット本文へHTMLやJSONの全コードを貼らず、ダウンロード可能なファイルとして作成します。

標準名:

- 内容モデル: `deck.json`
- HTML下書き: `deck-draft.html`
- 最終HTML: `deck.html`
- PDF: `deck.pdf`

ユーザーが名前を指定した場合は、その名前を優先します。HTMLとPDFは同じ基底名にします。

## 2. HTMLテンプレート

`03_DECK_TEMPLATE.html`をデザインと挙動の基準にします。次のマーカーを実データへ置換し、未置換のまま納品しません。

- `__DECK_TITLE__`
- `__SLIDES__`
- `__DECK_DATA__`
- `__DRAFT_BANNER__`
- `__PRINT_DISABLED__`
- `__PRINT_LABEL__`

テンプレートにはフォントデータを内蔵していません。`Noto Sans JP`が利用できない環境では、正本の順序に従い`Hiragino Sans`、`Yu Gothic`、`Meiryo`、`sans-serif`へフォールバックします。フォント差で意図しない改行が発生していないか確認します。

HTMLには最低限、次を含めます。

- 16:9、1600×900を基準とした各スライド
- 前後移動ボタンとキーボード操作
- 現在ページ／総ページ表示
- PDF印刷時に1スライド1ページとなるCSS
- 印刷時に操作UIを非表示にするCSS
- UTF-8の日本語表示
- 復元に使える`deck.json`相当の埋め込みデータ

## 3. iPad／iPhoneでの確認

生成環境から実際の利用者端末を操作できない場合、モバイル閲覧を確認済みと報告しません。代わりに次を確認し、利用者へ短く依頼します。

- viewport設定がある
- 横向き16:9で内容が切れない
- タップ可能な前後移動がある
- ファイル名と拡張子が正しい
- 外部ライブラリへの依存を最小限にしている

利用者には、iPadでHTMLを開けること、iPhoneでPDFを保存・再表示できることだけを確認してもらいます。

## 4. PDF

PDFはHTML確認後の別の依頼で作成します。利用できるファイル作成・コード実行環境でHTMLから生成し、次を確認します。

- ページ数がHTMLと一致する
- 1ページに1スライドだけが表示される
- 背景色と文字色が保持される
- ナビゲーションUIが混入しない
- 空白ページがない
- 文字切れ、重なり、意図しない改行がない

PDF生成または全ページ検査ができない場合は、その事実を伝え、未検査のPDFを完成版として納品しません。

## 5. 利用上限と中断

利用上限が近いと判断した場合、長い進捗説明や重複QAを増やしません。可能なら最新の`deck.json`またはHTML下書きを先に保存し、次だけを短く残します。

- 完了した工程
- 保存した成果物
- 未完了の工程
- 最初に行う次の操作
- PDF生成が承認済みか未承認か

上限回復後は、同じProjectの最新成果物と会話を確認し、完了済み工程をやり直さず再開します。

## 6. 修正

利用者の修正指示を、必要以上に専門用語へ言い換えません。「文字が多い」「このページが味気ない」「色を変えたい」といった自然な表現から、対象ページと意図を確認して修正します。

複数ページの構成変更は、修正版のページ構成を提示して承認を待ちます。単一ページの文言、色、文字サイズなどの限定修正は、影響範囲が明確なら直接実施できます。
