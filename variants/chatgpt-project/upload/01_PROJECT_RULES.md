# ChatGPT Project Adapter Rules

このファイルはChatGPT Free／Plusで共通して使用する実行規則です。`02_CANONICAL_SPEC.md`の内容を置き換えず、ChatGPTのProjectとファイル作成環境へ適用する方法だけを定義します。

## 1. 参照順序

1. このファイルで会話段階と参照範囲を判断する
2. `02_CANONICAL_SPEC.md`で適用するMUST／SHOULDを確認する
3. 制作時に`04_DECK_SCHEMA.json`で内容モデルを作る
4. `03_DECK_TEMPLATE.html`を基準にHTMLを作る
5. `05_MOBILE_RUNTIME.md`に従ってファイル納品、PDF、再開を処理する

同じチャットで変更されていないProjectファイルを繰り返し読み直さないでください。仕様をチャット本文へ復唱しないでください。

## 2. 会話段階

### 相談

ユーザーが意見、選択肢、構成案について相談しているだけなら制作しません。短く提案し、判断を待ちます。

### 不足確認

安全性、権利、事実性、対象範囲、成果物を大きく変える不足だけを質問します。質問が必要なら、原則1つの短い質問だけを提示して停止します。同じ回答内に制作条件を含めません。

### 制作条件の確認

質問への回答を受け取った次の応答では、ツールを使わずに次を提示して停止します。

- 対象者と用途
- タイトルと日付
- 表紙の任意項目
- 内容の流れと概算ページ数
- `standalone`または`presented`
- `warm_clean`または指定テーマ
- HTML下書きを先に納品し、PDFは次の依頼で作ること
- 重要な仮定、権利、安全性、事実性の条件

最後に「この内容で制作する」「内容を修正する」に相当する明確な選択を示します。

### 制作承認

提示した制作条件に対する明示的な承認だけを制作開始の合図とします。質問への回答、訂正、「続けて」「OK」だけを承認として扱いません。

## 3. 制作方法

- 承認前に広いWeb検索、構成の作り込み、HTML/PDF生成を行わない
- 承認後は必要な調査をまとめ、同じ検索やファイル読込を繰り返さない
- 根拠のない数値、事実、社内規程、引用、事例を作らない
- 各スライドの主要ジョブと主要メッセージを1つに絞る
- 文字を縮小して詰め込まず、文章短縮、レイアウト変更、ページ分割を優先する
- 装飾画像を探すためだけの検索をしない
- 既定テーマは`warm_clean`とし、グラデーションを使用しない
- 既定出力は自己完結型HTMLとPDFとする

## 4. Free／Plus共通の段階納品

### Stage A

明示的な承認後、`deck.json`と`deck-draft.html`を作ります。静的に確認できる内容、文字量、出典、ページ番号、ナビゲーション、印刷CSSを検査し、HTMLファイルだけを納品して停止します。

利用者には次の3点だけを確認してもらいます。

1. 話の順序と結論
2. 文言、数値、表、出典
3. 仮定、条件、次の行動

Stage AではPDFを作らず、全ページ画像や長いQAログも納品しません。

### Stage B

ユーザーがHTMLを確認してPDFを明示的に依頼した場合だけ、修正を反映した最終HTMLとPDFを作ります。可能な範囲で全ページを画像またはPDFページとして確認し、HTMLとPDFのページ数、順序、文字、背景、ページ番号を比較します。

検査できなかった項目をPASSとしません。PDFを生成できない場合は、HTMLを完成物として残し、失敗理由とiPadのブラウザ印刷による代替案を伝えます。

## 5. 既存成果物

既存HTMLがある場合は、HTMLを編集元として扱います。PDFは見た目の参照に使い、PDFだけを独立修正しません。

- 文言、色、単一要素の変更: 範囲が明確なら直接修正できる
- ストーリー、ページ数、複数ページの再構成: 修正後の構成案を提示し、承認を待つ
- HTMLに編集用データがない: 再構築方針を提示し、承認を待つ

## 6. 完了条件

実際にダウンロード可能な成果物が存在し、依頼内容、適用MUST、全ページの可読性、HTML/PDF整合を確認できた場合だけ完成と報告します。自動検査の成功だけで、人の確認を省略しません。
