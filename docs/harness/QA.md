# QAゲート

## ゲート

1. 制作前検査
2. 内容契約検査（調査・重要論点・比較軸・掲載先・出典）
3. 内容・構造検査
4. HTML生成検査
5. 視覚検査
6. PDF検査
7. 人間による最終確認

## 判定

- `MUST`: 未達ならPASS不可。
- `SHOULD`: 原則対応し、未対応理由を記録する。
- `MAY`: 任意の改善候補。
- `critical`と`major`が残る場合はFAIL。

自動修正回数に達しても合格扱いにはしません。解決しない場合は`needs_revision`または`blocked`として、問題、実施済み対応、推奨案を残します。

## ルールの適用順

```text
共通の安全・可読性MUST
  → 00〜60
  → デザインパック
  → ブランド
  → Run固有条件
```

下位ルールは上位MUSTを解除できません。題材固有の数値やページ構成は、共通QAではなくテストケースに残します。

内容契約の必須論点が`deck.json`の`context.content_coverage`へ割り当てられていない場合、掲載先に確認語がない場合、必要な出典が参照されていない場合は、HTML生成前にFAILとします。見た目が整っていても内容ゲートを通過しません。
