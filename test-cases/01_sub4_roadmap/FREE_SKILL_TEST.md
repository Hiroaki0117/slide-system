# Free Skill Test 01: Sub-4 Roadmap

## 目的

無料版Claudeで、上限到達前に最低1つのダウンロード可能な成果物を受け取り、次のターンでPDFまで完成できるかを検証します。入力内容はAI初心者が用意できる水準から改善しません。

## 事前準備

1. 別アカウントの無料版Claudeへ`dist/slide-system-free-v0.2.10.zip`だけを登録する
2. コード実行とファイル作成を有効にする
3. このテスト専用の新しいチャットを開き、`slide-system-free`を有効にする
4. プロジェクト仕様書、`EXPECTED.md`、`FREE_EXPECTED.md`、過去の生成物は添付しない

## 最初の入力

添付するのは`source/RUNNING_NOTES.md`だけです。次の2文を変更せず送ります。

```text
11/1の下関海峡マラソンでサブ4を目指したいです。
今の状況を添付したので、達成までのロードマップをスライドにしてください。
```

## テスト中の対応

1. 安全上重要な質問には、実際の状況を自然な言葉で答える。
2. 質問への回答後、Web検索、ファイル表示、コマンド実行、スキル再読込が1回も行われず、直後に制作条件が提示されて停止することを確認する。1回でもツールを使った場合は、その後に成果物が出ても`FAIL`とする。
3. 制作条件が正しければ「その内容でお願いします」と答える。
4. HTML下書きが添付されるまで、枚数、構成、色、レイアウト、出力形式を補足しない。
5. 承認後、Python・JavaScript・HTMLテンプレート・生成済み完全モデルの中身を表示せず、軽量ビルダーを1回実行してHTML下書きを返すことを確認する。
6. HTML下書きをダウンロードできることを確認する。5段階表は前半・後半へ分かれ、すべて表示されていることを確認する。2ページ目は大きな数字と説明文が分離され、週3回メニューは入力が長い場合だけ概要と曜日別詳細へ分かれていることを確認する。各曜日には`現状`、`維持・変更・中止`、`提案`、`進め方`、`理由`があり、RUNNING_NOTESの文面を変更案として再掲していないことを確認する。当日戦略の工程図は2行の条件表示と区間別説明に分かれ、同じ文言を重複させないことを確認する。検証が不合格の場合も、`検証未完了ドラフト`と表示されたHTMLが返り、同じターンで再試行しないことを確認する。
7. HTMLとともに、各週の距離、火・木・土の現状・判断・提案・理由、開始・中止条件の3点が確認事項として提示されることを確認する。
8. 修正がなければ、次のターンで「PDFもお願いします」とだけ送る。
9. PDFが全ページ画像化や一覧画像作成より先に保存され、最終HTMLとPDFをダウンロードできることを確認する。
10. 上限に達した場合は、検証合格済みHTMLの`PDF保存`を押し、ブラウザの印刷画面からPDFを保存できることを確認する。`検証未完了ドラフト`ではボタンが`PDF保存不可`となり、PDF化できないことを確認する。

上限に達した場合は、最後に受け取れたファイル、Claudeの最後の応答、どの段階だったかを保存します。HTMLを受け取る前に上限へ達した場合は`FAIL`です。

## 保存先

生成物は`output/free-v0.2.10/`へ保存し、結果を`RESULT.md`へ追記します。

## 既存成果物の回帰テスト

新しいチャットを使い、次をそれぞれ確認します。

1. v0.2.10で作ったHTMLだけを添付し、「当日戦略を3区間の図に修正してください」と依頼する。再調査や全構成の作り直しをせず、修正版HTMLを先に返すこと。
2. 同じHTMLとPDFを添付して限定修正を依頼する。HTMLを編集元、PDFを見た目の参照として扱うこと。
3. PDFだけを添付して修正を依頼する。全ページを確認し、再構築内容と変更点を提示して承認待ちで止まること。
4. 修正版HTMLの後に「PDFもお願いします」と送り、修正版PDFが作られること。

## ツール使用量の記録

次を`RESULT.md`へ記録します。

- 承認前の検索回数
- 質問回答後から制作条件提示までのツール呼び出し回数（期待値0）
- 承認後からHTML納品までの検索操作数、開いた出典ページ数、スキル・参照ファイル読込回数
- HTML納品までに表示された進捗メッセージ数
- HTML納品前に表示された`.py`、`.mjs`、テンプレートHTML、完全`deck.json`の数（期待値0）
- 軽量ビルダー実行回数（期待値1）
