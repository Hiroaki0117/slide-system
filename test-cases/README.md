# Test Cases

このディレクトリでは、スライド仕様が新しいClaudeチャットでも再現されるかを確認します。

テストの主対象は、AIやスライド制作に詳しくない人です。したがって、主テストでは整った依頼文や完成された原稿を用意しません。実際の利用者が送る短い依頼と、手元にある走り書き程度の資料から、Claudeが不足を補い、必要な確認だけを行い、仕様に沿った成果物を作れるかを評価します。

## 実利用テストの原則

- 依頼文は1〜2文の自然な言葉にする
- 添付資料は、利用者が普段作れる程度のメモにする
- モード、資料タイプ、テーマ、出力形式、枚数、レイアウトなどの内部設定を書かない
- AI向けに見出し、出典、計算、構成案を整えない
- 誤記や情報の抜けを過度に直さず、Claudeが確認・補完できるかを見る
- 最初の成果物が出るまで、改善用の追加指示を送らない
- `EXPECTED.md`と`RESULT.md`は評価者専用とし、Claudeへ添付しない

整った入力を使う比較用テストは、将来の回帰テストとして別に作成できます。ただし、製品としての使いやすさは実利用テストで判断します。

## 実行手順

1. Claudeプロジェクトに`PROJECT_INSTRUCTIONS.md`と`00_MASTER.md`〜`60_QA.md`を登録する
2. テストごとに新しいチャットを開始する
3. `REQUEST.md`に記載された利用者向け資料だけを添付し、指定の依頼文をそのまま送る
4. Claudeから確認があれば、利用者として分かる範囲で自然に答える
5. 最初の成果物が出るまで、追加のデザイン指示や修正指示を送らない
6. 成果物を`output/`へ保存し、`EXPECTED.md`と比較する
7. `RESULT.md`へ初回出力、問題、修正、再検証を記録する

カスタムスキル版は、対象ZIPだけを登録し、プロジェクト仕様書を同時に添付しません。無料版では、HTML下書きが納品されたことを確認してから、次のターンでPDF作成を依頼します。

## 判定

- `PASS`: 期待条件を満たした
- `FAIL`: 必須の期待条件を満たさなかった
- `WARN`: 合格可能だが、改善余地または判断が必要な点がある
- `N/A`: 今回は対象外
- `NOT_VERIFIED`: 未実行または環境上確認できなかった

最終判定は、該当するすべての`MUST`が`PASS`または理由を記録した`N/A`であることを条件とします。

## 問題の分類

| 分類 | 意味 |
|---|---|
| `implementation` | 仕様は明確だが、生成物が従っていない |
| `spec_gap` | 仕様が不足、曖昧、または矛盾している |
| `environment` | 無料プラン、生成機能、変換、閲覧環境による制約 |
| `input` | 元資料または依頼内容に原因がある |
| `preference` | 合否ではなく、好みや微調整に属する |

`preference`だけを理由に仕様を増やしません。複数の試作で繰り返す問題か、読みやすさや再現性に影響する問題を優先して仕様へ反映します。

## ChatGPT／Claude モバイル比較

`test-cases/cross-platform/`では、PCを持たずiPad・iPhoneだけを使う利用者を想定し、同じ依頼と元資料を次の4環境で比較します。

- ChatGPT Free
- ChatGPT Plus
- Claude Free
- Claude Pro

仕様と入力は共通にし、成果物と実行記録を環境別に分離します。最初のケースは`cross-platform/01_mobile_internal_training/`です。

なお、4環境で同じスライドを生成して品質を競うテストと、4プランの違いを説明するスライドは別物です。後者の成果物は`02_ai_mobile_plan_comparison/`へ保存します。

プラン比較の成果物は、利用者が自分の候補だけを読みやすいように次の3資料へ分けています。

- `split/chatgpt/`: ChatGPT Free・Plusの詳細ガイド
- `split/claude/`: Claude Free・Proの詳細ガイド
- `split/comparison/`: ChatGPTとClaudeを選ぶための1枚比較表

元の統合版は、全体を一度に確認する共通資料として`output/v0.1.0/`に残します。
