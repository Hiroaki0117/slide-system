# Test Cases

このディレクトリは、スライド仕様が新しいClaudeチャットでも再現されるかを検証するための固定テストケースを管理します。

テストケースは仕様書や作例ではありません。期待結果と実際の結果を比較し、仕様不足、生成上の問題、環境制約を発見するための記録です。テストケースの内容が仕様書と異なる場合は、仕様書を優先します。

## 実行原則

1. Claudeプロジェクトに`PROJECT_INSTRUCTIONS.md`と`00_MASTER.md`〜`60_QA.md`を登録する。
2. テストごとに新しいチャットを開始する。
3. `REQUEST.md`の依頼文を変更せず送信し、指定された元資料だけを添付する。
4. 制作前の確認では、テスト手順に記載された回答を選ぶ。
5. 追加指示で結果を誘導せず、最初の出力を保存する。
6. 生成物を`output/`へ保存し、`EXPECTED.md`と比較する。
7. `RESULT.md`へ結果、問題、修正、再検査を記録する。

## 判定

- `PASS`: 期待条件を満たした。
- `FAIL`: 必須の期待条件を満たさなかった。
- `WARN`: 合格可能だが、改善余地または判断が必要な点がある。
- `N/A`: 今回は対象外。
- `NOT_VERIFIED`: 環境上確認できなかった。

テストケースの最終判定は、該当するすべての`MUST`が`PASS`または理由を記録した`N/A`であることを条件とします。

## 問題の分類

発見した問題は次のいずれかに分類します。

| 分類 | 意味 |
|---|---|
| `implementation` | 仕様は明確だが、生成物が従っていない |
| `spec_gap` | 仕様が不足、曖昧、矛盾している |
| `environment` | 無料プラン、生成機能、変換、閲覧環境による制約 |
| `input` | 元資料または依頼内容に原因がある |
| `preference` | 合否ではなく、好みや微調整に属する |

`preference`だけを理由に、すぐ仕様を追加しません。複数の試作で繰り返す問題か、読みやすさや再現性に影響する問題を優先して仕様へ反映します。
