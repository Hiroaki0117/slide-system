## 1. 想定される制作条件

依頼文と仕様から、次が選択されることを期待します。

| 項目 | 期待値 | 重要度 |
|---|---|---|
| 対象者 | 社内の新任チームリーダー | `MUST` |
| 対象者プロファイル | `beginner` | `MUST` |
| 利用目的 | 勉強会後に配布し、知識共有を続ける仕組みを理解してもらう | `MUST` |
| コンテンツモード | `standalone` | `MUST` |
| 資料タイプ | `explain` | `MUST` |
| デザインテーマ | `warm_clean` | `MUST` |

| 言語 | 日本語 | `MUST` |
| 枚数 | 8〜12枚を目安に内容から提案 | `MUST` |

## 3. 内容の期待結果

ページ数や順序の完全一致は求めませんが、資料全体で次を扱うことを期待します。

| ID | 期待結果 | 重要度 |
|---|---|---|
| `C01` | 知識共有が続かない原因を、個人の意欲ではなく仕組みの問題として説明する | `MUST` |
| `C02` | 「残す・整える・使う」の3段階を、関係が分かる形で説明する | `MUST` |
| `C03` | 4週間の検証用データを、原稿と同じ数値・単位で示す | `MUST` |
| `C04` | 数値の変化を因果関係として断定しない | `MUST` |
| `C05` | 投稿を5分以内にするなど、続けるための具体策を含める | `MUST` |
| `C06` | 小さく始める実行案を示す | `MUST` |
| `C07` | 外部の事実、人物、調査結果を根拠なく追加しない | `MUST` |
| `C08` | 原稿内の検証用データであることを明示する | `MUST` |
| `C09` | 資料だけで前提、仕組み、結果、注意点、まとめを理解できる | `MUST` |
| `C10` | 一般的な「ありがとうございました」だけで終わらず、要点または次の行動で終える | `MUST` |

推奨する流れは次のとおりです。これは参考であり、同じストーリーを実現できれば別構成も合格とします。

1. 表紙
2. なぜ知識が残らないのか
3. 続かない3つの原因
4. 「残す・整える・使う」の循環
5. 各段階の具体的な行動
6. 4週間の検証用データ
7. 数値の読み方と制約
8. 小さく始める導入方法
9. まとめ・次の行動
10. 出典

## 6. 出典の期待結果

原稿内の数値を使用するページでは、短い出典として次に相当する表示を行います。

```text
出典: 検証用サンプル [S1]
```

資料末尾の出典ページには、`SOURCE.md`に記載された[S1]の完全情報を掲載します。外部情報を追加した場合は、その情報と素材も追跡可能な形で記録します。

## 7. このケースで検証しないこと

次は別のテストケースで確認します。

- `presented`モード
- `pptx_pdf`とPPTXの編集可能性
- 発表者ノート
- `training`の演習と理解確認
- 依頼者指定写真の優先使用
- 外部画像の検索と利用条件
- モバイル表示
- テンプレートまたはブランド指定

## 8. 合格条件

- すべての`MUST`が`PASS`または理由を記録した`N/A`
- 必須項目に`NOT_VERIFIED`がない
- 残った`WARN`が`RESULT.md`へ記録されている
- HTMLとPDFの実ファイルが`output/`に保存されている
